# Go-to-market plan

## Positioning

**Category:** a focused network workspace for e-ink, not a general-purpose app
store. **Enemy:** carrying a bright, distracting second screen for simple
remote tasks. **Proof:** five integrated tools, real touch input tests, no
telemetry, local profiles, and a physical-device compatibility matrix.

## Launch sequence

### Phase 1 — validate demand (now)

- Publish the product page and open-source download.
- Invite voluntary support without gating features.
- Recruit 10 design partners from the reMarkable/XOVI community.
- Success gate: 25 qualified leads, 10 installs, 5 people willing to pay.

### Phase 2 — reliable community release

- Deploy the signed update feed behind the production HTTPS domain.
- Publish exact compatibility notes and a recovery guide.
- Offer optional guided setup without promising broad firmware support.

### Phase 3 — repeatable acquisition

- Publish short proof videos: SSH command, readable article, RDP terminal, and
  offline RSS. Each starts with the outcome in the first three seconds.
- Create compatibility pages for each tested firmware combination.
- Invite community maintainers to audit licence and install documentation.
- Publish the PaperDesk Care updater threat model and signing-key policy.

## Message hierarchy

1. Turn the tablet you already own into a calm network desk.
2. Five tools designed for e-ink, not squeezed onto it.
3. Tested on real hardware with reversible installation and no telemetry.
4. Independent community software; exact compatibility is explicit.

## Channels

- reMarkable/XOVI GitHub and community forums: technical launch notes and
  transparent source availability.
- Reddit and e-ink communities: outcome video, honest limitations, no spam.
- Hacker News / Lobsters: engineering story about e-ink refresh and input.
- YouTube: one 60-second overview and five feature-specific clips.
- Direct outreach: 20 researchers/sysadmins already using a reMarkable 2.

## Metrics

Track visits, CTA clicks, qualified leads, install completion, seven-day active
use, support minutes per install, refund requests, and firmware-related
failures. Do not add invasive analytics; aggregate server logs are enough for
the validation phase.
