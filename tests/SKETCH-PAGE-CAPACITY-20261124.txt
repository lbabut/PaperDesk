Paper Sketch page capacity UAT, 24 November 2026

Supersedes the uninstalled limit-message-only candidate documented in
SKETCH-NEW-PAGE-20261124.txt. Owner asked why a page limit is needed and
confirmed the drawing saved/closed before interface restart.

The number 12 was a hard-coded UI/decoder restriction, also duplicated in
native documentSlots (tool-state persistence and deleted-page cleanup).
Pixels/material are loaded per current page, not for the entire notebook.
This patch removes that fixed page-count ceiling in all three places.
It does NOT promise unlimited storage or constant navigation time for huge
notebooks. Existing unique cache IDs, stroke validation/point budget, atomic
file replacement and load bounds stay. Native saves now refuse UTF-8 metadata
over the existing 16 MiB read bound, including after tool-state insertion.
Decoder rejects overlarge metadata before JSON parsing. Failure keeps the
current drawing dirty/in memory. No rendering or input cadence changes.
